# Очистка изображений номенклатуры УТ 11.5

Отдельная внешняя обработка `ut115_clear_item_images_1_0_0.epf` для Управления
торговлей 11.5 (целевая версия пользователя — 11.5.27.107).

Обработка **физически удаляет выбранные присоединённые изображения**, хранящиеся
в информационной базе, через стандартное удаление БСП. Ссылки на выбранные файлы
в реквизите `Номенклатура.ФайлКартинки` очищаются. Файлы, хранящиеся во внешних
томах, в список не включаются. Требуется пользователь с полными правами.

Перед использованием сделайте резервную копию базы. Физическое удаление
восстанавливается из резервной копии. Первую проверку выполните в копии базы.

1. **Закройте форму синхронизации картинок** и остановите её другие запуски:
   открытая синхронизация может хранить старые картинки и ссылки в кэше.
2. Откройте EPF через «Файл — Открыть» либо зарегистрируйте его как дополнительную
   обработку. Регистрация открывает форму, действия при открытии не удаляют данные.
3. При необходимости установите отборы «Только варианты _150x150» и/или
   «Только помеченные файлы». По умолчанию подходят все изображения из базы.
4. Нажмите **«Показать изображения»**. Появится таблица: отметка, файл,
   номенклатура-владелец, имя, расширение, число основных ссылок и результат.
   Просмотр не меняет данные. Изначально строки не отмечены.
5. Отметьте нужные файлы вручную или нажмите **«Выбрать все»**. «Снять выбор»
   убирает отметки. После изменения отборов обновите список.
6. Нажмите **«Удалить выбранные»** и подтвердите физическое удаление.
   Подтверждение по умолчанию — «Нет».
7. Дождитесь результата. В каждой обработанной строке будет статус/причина,
   в заголовке — счётчики. «Остановить» прекращает следующие этапы после
   завершения текущей операции; выполненные удаления сохраняются.
8. После очистки **заново откройте синхронизацию** и загрузите картинки.

Для полной перезагрузки сочетания «коллекция + дизайн + форма» очистите картинки
у всех его размерных вариантов: оставшаяся картинка другого варианта может быть
повторно использована синхронизацией по согласованному правилу.

## Область отбора

Кандидаты принадлежат элементам справочника номенклатуры и имеют тип хранения
`ВИнформационнойБазе`. Изображения определяются по расширению: JPG, JPEG, PNG,
GIF, BMP, TIF, TIFF, WEBP, SVG, ICO, AVIF, HEIC, HEIF (без учёта регистра и начальной
точки). Отбор `_150x150` проверяет суффикс имени, которым синхронизация называет
свои уменьшенные варианты.

Список хранится в снимке, привязанном к форме. В удаление принимаются только
выбранные ссылки из просмотренного снимка. При удалении повторно проверяются
тип, владелец, имя, расширение, хранение в базе и отборы. Изменение имени/владельца/
расширения после просмотра требует обновления списка.

Сброс основной картинки охватывает **все элементы/группы номенклатуры, ссылающиеся
на выбранный файл**, в том числе при совместном использовании картинки.

## Как выполняется удаление

Каждый выбранный файл обрабатывается в отдельной транзакции:

1. Файл блокируется и повторно проверяется по снимку.
2. Очищаются основные ссылки `ФайлКартинки`, ведущие на этот файл.
3. Файл помечается на удаление в рамках той же операции.
4. Вызываются `Обработки.УдалениеПомеченныхОбъектов.ПараметрыУдаления()` и
   `Обработки.УдалениеПомеченныхОбъектов.УдалитьПомеченныеОбъекты(...)` с явным
   массивом из **одного выбранного файла**, в стандартном режиме.
5. Проверяется результат БСП и фактическое отсутствие записи файла.
6. Фиксируется транзакция. При отказе/ошибке изменения по файлу откатываются,
   включая основные ссылки и пометку удаления.

Общая очистка ссылок в местах использования отключена. При препятствующих
деловых ссылках стандартное удаление откажет; причина появится в строке.
Служебные связи, данные файла и связанные версии обслуживают штатные механизмы
БСП. Прямых SQL-изменений, самостоятельной очистки хранилища, отключения
обработчиков через `ОбменДанными.Загрузка` и собственного повышения привилегий
в обработке нет.

Размер пакета по умолчанию — 10, допустимый максимум — 50. Дополнительно
проверяется бюджет 2 секунды после каждого файла. Длительная отдельная операция
может превысить бюджет; она завершается перед остановкой.

## Проверки и ограничения

Пройдены 7 автоматических проверок: сборка и повторная распаковка EPF,
идентификаторы/привязки формы, соответствие реквизитов метаданным, область
стандартного удаления и отсутствие исходных API-ключей.

Код удаления исполнен через OneScript с тестовыми транзакциями/БСП:

- выбранное изображение и две основные ссылки удаляются, другие файлы остаются;
- отказ из-за связей, ошибка записи, ошибка удаления и ложный «успех» БСП
  откатывают данные, пометку и основные ссылки;
- неподходящие расширения, внешний том, чужой владелец и устаревший снимок
  отклоняются;
- проверены список разрешённых ссылок, дубли выбора, остановка и поля только
  для чтения.

Сигнатуры БСП сверены по открытому коду
[ssl_3_1](https://github.com/1c-syntax/ssl_3_1/tree/da8aa1fcef273f6e61bbb7ec9ea3107cac32cabc):
модули `РаботаСФайлами`, `РаботаСФайламиСлужебный` и менеджер обработки
`УдалениеПомеченныхОбъектов`.

В среде подготовки нет платформы 1С и вашей базы. Реальные операции удаления,
вложенные транзакции БСП, права и нажатия кнопок в УТ не проверялись. Здесь
никакие данные вашей базы не изменялись. Источники BSL приложены для проверки.

В этой обработке нет ключей API, архив предоставляется **без пароля**.
