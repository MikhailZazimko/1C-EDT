# Исправления XDTO для проверки в основной УНФ

Подготовлены по двум файлам `Package.xdto`, предоставленным пользователем
27.10.2026. Папка относится к основному проекту `УНФ_Демо_КМК`; при обновлении
ветки расширения эти пакеты не заменяются в основной УНФ автоматически.

## Что изменено

### ОтправкаРеестровПВСО — 27 числовых ограничений

В пространстве `http://pilot.fss.ru/1.7` найдены ровно 27 анонимных типов с
`variety="Atomic"`, списком `enumeration` и базовым типом
`fssnilinteger1`/`fssnilinteger2`. Базовые типы являются объединениями целого
числа заданной разрядности и пустой строки. Это соответствует 27 сообщениям EDT.

В этих 27 местах базовый тип заменён на `xs:integer`. Списки кодов не изменены.
Каждый список содержит только непустые целые числа, укладывающиеся в исходное
ограничение `totalDigits`. Пустая строка уже исключена самим перечислением.
Поэтому числовое ограничение с прежним списком кодов задаёт то же множество
допустимых XML-значений. Проверяется также приём ведущих нулей, знака и пробелов
в целых числах согласно XML Schema.

Именованные типы `fssnilinteger1/2` остаются объединениями: другие поля по-прежнему
допускают пустое значение. Строковые коды, включая `IdType` со значениями `01`,
`03` и т. п., не превращаются в числа. Даты, ограничения длины, остальные типы,
имена и пространства имён сохраняются побайтно.

### MobileClientIntegration — явная граница Company.name

У `Object.name` указана нижняя граница 0. У переопределяющего `Company.name`
граница не указана; значение по умолчанию 1 сделано явным: `lowerBound="1"`.
Тип строки и `nillable="true"` сохранены. Обязательность свойства не ослабляется.

Важное ограничение диагностики: исходные границы 1 и 0 сами по себе не нарушают
правило `производная >= базовая`. Поэтому это нормализация объявления для
повторной проверки EDT, а не подтверждение воспроизведения её сообщения в облаке.
Пользователь предоставил `MobileClientIntegration.mdo` с UUID
`beb2d544-c8cb-443d-b197-3cf5d8879523`: пространство имён в нём совпадает с XML
(`http://www.1c.ru/SB/MobileExchange`), ошибка привязки пакета не подтверждена.
Если сообщение остаётся после пересборки основной УНФ, нужно исследовать
описание пакета, разрешение типов и диагностику EDT; понижать границу до 0 для
сокрытия ошибки не следует.

## Как применить в тестовом проекте EDT

1. Сохранить копии исходных файлов основной УНФ.
2. Скачать `unf-xdto-fixed.zip` и распаковать в отдельную папку. Архив содержит
   только два файла в `src/XDTOPackages/...`.
3. Скопировать оба файла в соответствующие папки основного проекта
   `УНФ_Демо_КМК`, сохранив существующие файлы `.mdo`:
   - `src/XDTOPackages/MobileClientIntegration/Package.xdto`;
   - `src/XDTOPackages/ОтправкаРеестровПВСО/Package.xdto`.
4. В EDT обновить ресурсы основного проекта (F5), затем выполнить
   «Проект → Очистить…» для **основной УНФ** и дождаться окончания проверки.
   Очистки одного расширения для проверки этих пакетов недостаточно.
5. Проверить оставшиеся сообщения и обновление тестовой ИБ через EDT.
   Для использования этих обменов проверить штатное формирование и чтение XML
   в платформе 1С, включая типы присваиваемых значений. XSD-проверки в облаке
   не подтверждают поведение фабрики XDTO и прикладного кода УНФ.

Для просмотра всех изменений приложен `unf-xdto.patch`. `manifest.json` содержит
SHA-256 исходных и исправленных файлов, строки и точный список замен.

## Проверки и воспроизводимость

```bash
python3 tools/repair_unf_xdto.py --mobile /path/MobileClientIntegration/Package.xdto --fss /path/ОтправкаРеестровПВСО/Package.xdto
python3 -m unittest discover -s tests -v
```

Генератор требует исходные файлы и останавливается при изменении проверяемой
структуры. XML не сериализуется заново: меняются только перечисленные атрибуты,
сохраняются CRLF и объявления пространств имён. Восстановление исходников из
манифеста проверяется по SHA-256 загруженных файлов.

При наличии `lxml` тесты сравнивают исходные/исправленные числовые ограничения
через XML Schema на 21 897 вариантах значений. Дополнительно проверяются
строковые коды с ведущими нулями и поля с допустимой пустой строкой.
EDT 2026.2.2 и платформа 1С в облаке отсутствуют; итоговый результат их проверки
подтверждается на стороне пользователя.
